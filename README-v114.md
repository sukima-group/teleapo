## v114 で変えたこと

### ⑴ 前回の結果（前回なんて断られたか）

| 出る場所 | 出るもの |
|---|---|
| 架電のカード（会社名・住所の下） | 「架電済みの会社です（前回 11/12 10:05・柏木）　これまで 3回」／**結果（大きく・色つき）**／📝 メモ／💬 切り返し／その前の結果／元シートの架電履歴／出どころ |
| 通話の画面（担当者の下） | 同じもの（通話しながら見られます） |
| リストの各行 | 1行で「前回 11/12 10:05・柏木：不要・NG ｜ 本社で一括（3回）」。絞り込みに「前回の結果あり」を足しました |
| 進み具合の帯の「次にかける」 | 「2件目 ◯◯株式会社（前回 番号不通）」 |

結果の色：断り・不要・NG・受付ブロックなど＝赤、アポ＝緑、再架電・検討など＝橙、不在＝灰、不通＝灰。

前回の結果は、次の3つのうち **いちばん新しいもの** を出します。

1. **元シート**：元シートの「結果」「メモ」「日付」「時刻」「架電者」の列と「架電履歴（自動）」。サーバーが取込のときにタブの G〜L 列へ控え、ログイン時の同期で届きます。そのあと元シートに書かれた結果・メモも、同期のあと裏で読み直して出します（1人 30分に1回まで）。
2. **全員の架電記録**：「架電結果」シートの、**同じ電話番号への架電**（ほかのリスト・ほかの方の分も）。直近 400日・最大 8万行から、電話番号ごとの索引をチームで1つ作ります（作ってから 30分たつと、次に取りに来た端末の分で作り直します。作り直している間は、前の索引を返します）。アプリは同期のあとで裏で取りに行きます（20分に1回まで）。
3. **この端末の履歴**：かけた直後から出ます。

**同期（ログイン）は遅くなりません。** v113 で分かったとおり、同期の中で「架電結果」を読むと時間がかかるため、同期で返すのはタブの控えだけです。全員の架電記録は、同期とは別に裏で届きます。索引を作っている間も、通話結果の保存は止まりません（索引づくりは、ほかの保存が使う鍵を使いません）。

### ⑵ 元シートの順番どおりに架電する（飛ばさない）

- **次にかける先は、「元シートのいちばん上の、まだ架電していない行」** です（いまの行を除く）。手前に戻るときは「↩ 元シートの順番どおり、まだ架電していない「◯◯株式会社」（2件目）からかけます」と出ます。
- **ログイン・開き直しのときも、いちばん上の未架電から** 始めます（通話の途中で開き直したときは、その行のまま。自動の同期では、開いている行を動かしません）。
- リストから好きな行を選んでかけることは、これまでどおりできます。かけ終わると、手前の未架電に戻ります。
- **飛ばすのは、架電済み・NG・アポ済み（電話番号が同じ）・スキップの行だけ** です。リストの行に「🚫 NG のため飛ばします」「🎯 アポ済みのため飛ばします」と理由を出します。
- 進み具合の帯に「（順番どおり・飛ばさない）」と、**次にかける3件**（前回の結果つき）、「飛ばす行：NG ◯・アポ済み ◯・スキップ ◯件」を出します。
- 管理者の画面 →「🧭 架電の順番（v114）」で切り替えられます。「元シートの順番どおり」（はじめの設定）／「いまの行の次から」（v113 までの動き。手前の未架電は最後に戻る）。出勤中の端末には2分以内に届きます。

### ⑶ アポ済みの判定は電話番号で

電話番号が同じアポがある行は、これまでどおり飛ばします。会社名だけが同じで電話番号が違う行は、飛ばさずに架電のカードへ「⚠ 同じ会社名でアポがあります（そのアポの商談日・担当者・電話番号）。電話番号が違うので、別の事業所として架電します」と出します。

### ⑷ 取込で、元シートの結果ごとに「架電する・しない」を選ぶ（管理者）

管理者の画面 →「元スプレッドシート連携」→「取込」の下見で、元シートに結果が入っている行の扱いを選びます。

| ボタン | 動き |
|---|---|
| **すべて架電する**（前回の結果を見ながら） | 結果が入っている行も、未架電として順番どおりにかけます |
| **すべて架電済みにする**（結果が空の行だけ架電） | v113 の「架電済みにする」と同じ |
| **結果ごとに選ぶ**（例：不要・NG は架電しない） | 元シートの結果の値と件数がボタンで並びます（数は例：「不要・NG 412」「不在 230」「受付ブロック 96」）。**架電しない結果を押して選ぶ** と、「架電しない：508行 ／ 架電する（前回の結果を見ながら）：330行」と数が出ます。選んだ結果の行だけ架電済みにします |

取込のあとの知らせ：「元シートに結果が入っていた 3行は架電済みにしました（不要・NG・アポ獲得）／ほかの 3行は、前回の結果を見ながら架電します／前回の結果 6行を控えました」。

### ⑸ 取り込み直しで、架電済みの印を「架電結果」からも引き継ぐ

同じリストを取り込み直したとき、v113 は前のリストとの突き合わせだけで「架電済み」の印を引き継いでいました。v114 は、**その人・そのリストの、いまの周回の「架電結果」** からも、電話番号と会社名（電話番号だけ・会社名だけも）で探して、新しいリストの行に印を付けます。知らせ（数は例）：「架電済み 120件を引き継ぎました（続きから架電できます）（うち 35件は、架電結果から会社で探して引き継ぎ）」。

### ⑹ 順番の点検（管理者）

「🧭 架電の順番」のカードに、人ごとに **「架電済み 40／200件・前回の結果あり 120件」**（数は例）と、**いちばん先まで架電した行より手前に残っている未架電** を出します（「⚠ 手前に未架電 12件（3件目 ◯◯株式会社 から）」／「✓ 飛ばしている行はありません」）。NG・アポ済みの行は、アポインターの画面でも飛ばすので数に入れず、「ほかに、NG・アポ済みで飛ばす行 ◯件」と別に出します。「🔄 全員の状況を同期」のあとに出ます。順番どおりの設定なら、次はこの行からかけます。

## 調べた設計と、当てはめた結果

**先にお断り**：調べたのは、発信システム（VICIdial・Genesys・Bright Pattern・NICE など）の、公開されている管理者向けの説明書と解説、国内の製品の比較記事です。国内のテレアポ会社が社内で使っている設定の中身は、公開されている情報では確かめられませんでした（出典は末尾）。

| 発信システムの部品 | 調べて分かったこと | この仕組みへの当てはめ（v114） |
|---|---|---|
| **次にかける列（ホッパー）** | VICIdial は、「架電対象の結果」に入っていて、リストを戻してから（リセット後）まだ架電していない先だけを、次にかける列に入れます。列の並びは「リストの順番」の設定で決まります | 次にかける先＝「まだ架電していない行」のうち、元シートのいちばん上（⑵）。次にかける3件を画面に出す |
| **リストの順番（リスト・オーダー）** | 「DOWN」は、リストに先に入れた先からかける設定です | はじめの設定を「元シートの順番どおり」に。v113 の動き（いまの行の次から）は、設定で選べるように残した |
| **架電対象の結果（ダイヤル・ステータス）** | リストを戻すと、架電対象に決めた結果の先だけが、もう一度かけられます | 取込で「結果ごとに選ぶ」（⑷）。不要・NG など、架電しない結果を選ぶ |

**再現性のための作り**

- 次にかける先は、**リストと「架電済み」の印だけで決まります**（どの端末でも、同じリスト・同じ印なら同じ行）。印はサーバーの「リスト進捗」と「架電結果」から作るので、端末を替えても変わりません。
- 前回の結果は、出どころ（元シート／全員の架電記録／この端末）を画面に出します。
- 取込の選択（すべて架電する・結果ごとに選ぶ）は、監査ログに残ります。順番の設定も、架電ルールと同じく監査ログに残ります。

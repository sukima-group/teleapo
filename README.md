## 調べた設計と、当てはめた結果

**先にお断り**：調べたのは、発信システム（Genesys・NICE CXone・Webex・Convoso・Bright Pattern・JustCall など）と Zoom の、公開されている説明書・解説です。国内のテレアポ会社が社内で使っている設定の中身は、公開されている情報では確かめられませんでした（出典は末尾）。

| 発信システムの部品 | 調べて分かったこと | この仕組みへの当てはめ（v115） |
|---|---|---|
| **プレビュー方式のスキップ** | Webex の発信キャンペーンは、発信前の画面で「スキップ（ほかの先へ）」と「外す（もうかけない）」を選べ、管理者がどちらも使えなくすることもできます。Genesys の利用者の例では、スキップの理由をリストの列に書き戻し、後ろへ回す・予約して掛け直す、発信禁止の理由なら二度とかけない、という運用が紹介されています。NICE CXone では、かけずに結果だけ付ける・後の時刻に予約し直す、を選べます | スキップのときに理由を選ぶ（⑶）。理由ごとに戻す時刻を決め、サーバーに残す。「番号・会社が違う」は管理者が確認して、NG にするか戻す |
| **ベスト・タイム・トゥ・コール** | Genesys の発信システムには、時刻ごとに発信数・つながった数・成果の率を並べる報告書があります | 時間帯ごとの接続率（⑷）。チーム全体と、いまのリストの分 |
| **架電できる時間（コール・タイム）** | Convoso・Bright Pattern・JustCall などは、キャンペーンごとに発信してよい時間を決め、その外ではかけない・時間内に回す仕組みを持っています | 架電の時間帯（⑸）。外では知らせる（止めない） |
| **掛け直しの間隔** | NICE の説明書は、休みを24時間にすると毎日同じ時刻にかけることになるため、27・29・31時間のようにずらすことを勧めています。JustCall も、同じ時間帯に二度かけないことを勧めています | 不在の掛け直しで、前回と同じ時間台を避ける（⑹） |
| **電話（CTI）との連携** | Zoom Phone は、`zoomphonecall`・`tel`・`callto` のリンクで Zoom のアプリを開いて発信できます（Android は対象外）。通話の記録は、管理者用の API（通話履歴）で取り出せます | Zoom Phone で発信・通話履歴の取り込み（⑵） |

- スキップの理由と戻す時刻は、サーバーが決めて「スキップ記録」に残します。どの端末でも、同じ時刻に同じ行が戻ります。
- 接続率は、全員の架電結果から、同じ数え方で出します。
- 架電の時間帯・Zoom Phone・掛け直しの設定は、架電ルールと同じく監査ログに残ります。

**入れていないもの**

| 部品 | 入れていない理由 |
|---|---|
| 予測発信・複数回線への同時発信 | 電話回線の側のシステム（CTI）の機能で、スマホの電話アプリ・Zoom のアプリで発信するこの仕組みでは作れません |

| 接続率の高い時間帯の先から並べ替える | 元シートの順番どおりにかけるご依頼（v114）と合わないためです |

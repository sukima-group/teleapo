## ⑴ アカウントの削除（坂上順子 093・浜田敏幸 095）

ご依頼に「浜田敏幸 095」が2回書かれていたため、同じアカウントの重複として扱いました。名簿に同じ行が2つあれば、両方消します。

- **消すもの**（新しい版をデプロイしたあとの最初のアクセスで、自動で1回だけ）
  - 「アポインター名簿」の行、暗証番号（アカウント認証）
  - 外部連携設定・録音設定・KPI目標・架電位置・現況の、その人の行
  - その人の架電リストのタブ（空なら削除。データがあれば「旧_坂上」「旧_浜田」に名前を変えて残します）
  - 設定ブロックの名簿（`CONFIG.ROSTER`）と、コードに書かれていた2人のメールアドレス
- **残すもの**：架電結果・勤怠・アポイント・シフト申請などの記録（報酬や請求の計算に必要なため）
- **使えなくする**
  - サーバーは、削除した PIN からの要求を断ります（古い画面を開いたままの端末からも使えません）。
  - 端末は、名簿の控え・その人の端末内のデータ・ログイン状態を消します。PIN を入れても「このアカウントは削除されています」と表示します。
- 消すのは「PIN と氏名の両方が一致するもの」だけです。将来、同じ PIN を別の方に割り当てても、その方には影響しません。
- 管理者の画面の先頭に「削除したアカウント：削除済み」と出ます。残っているときは「いま削除する」を押すか、エディタで `accountDeleteNow` を実行します。

## ⑵ 元シートの順番どおりに、ズレずに架電する

### v109 で確かめた仕組み（★＝実際に動かして再現したもの）

**アポインターの画面**

1. ★ **結果を、発信した会社ではなく「保存した瞬間に表示していた行」に記録していた。**
   アプリを開いてすぐ発信し、通話中に裏の同期でリストが入れ替わると、別の会社の結果になりました。電話から戻ったときの位置の復元でも、行が動くことがありました。
2. ★ **再架電のお知らせ（🔔 今すぐ発信）からかけた通話が、そのとき表示していた別の会社に記録されていた。**
   「会社01」にかけたのに、結果の入力画面は表示中の「会社04」で開き、会社04 の行（元シートも）に結果が付きました。会社04 は架電していないのに、次へ進んで飛ばされました。
   また、再架電リストの電話番号からかけた通話は、どこにも記録されませんでした。
3. ★ **「架電済み」の印を、端末の中の「きょうの履歴」と「行の番号」だけで決めていた。**
   同期すると印が消え、翌日はすべて「未」に戻り、別の端末では分かりませんでした。
4. ★ **位置が分からないとき、「履歴にある電話番号の行を飛ばした最初の行」から始めていた。**
   前のリストでかけた番号や、同じ番号の別の行まで飛ばしていました（間が空く）。「再同期」を押すと、リストが同じでも1件目に戻りました。
5. リストの最後まで進むと、黙って1件目に戻っていた。オートコールは1件で止まっていた（「次へ」の処理が結果を返していませんでした）。
6. 取り消し（保存直後の「取消」）が、送信待ちの間はサーバーに届かず、元シートに結果が残った。

**サーバー（元シートへの反映）**

7. ★ 取込のあとで元シートに行を足す・並べ替えると、反映が「会社名不一致」で書かれず、空白が残った。
8. ★ 同じ会社に2回かけても、元シートは最初の結果のままだった（自分が書いた値も「手入力」とみなして、上書きしませんでした）。
9. 反映は退勤時と定期実行だけで、その間は元シートが古いままだった。

### 修正

- **発信した瞬間の架電先（会社・電話番号・元シートの行・リスト）を固定し、結果は必ずそこへ記録します。**
  - 通話中は、リストの入れ替えを待たせます（保存したあとに反映します）。
  - 再架電のお知らせ・再架電リストからの発信も同じです。結果の入力画面は、かけた会社で開きます。保存したら、発信の前に表示していた行へ戻ります。
  - いまのリストに無い会社への再架電は、その会社の名前で記録し、リストの行には付けません。
- **架電済みの印は「元シートの行」で持ちます。** サーバーの「リスト進捗」シートと端末の履歴から作るので、同期・日付・端末が変わっても消えません。
- **「次へ」は、いまの行より後ろの「まだ架電していない行」です。** 無ければ手前の未架電へ戻り、すべて済んだら知らせます（黙って1件目に戻りません）。
- 手前に未架電の行が残っているときは、ホームに「⚠ 手前に、まだ架電していない行が N件あります」と出し、「↩ そこへ戻る」で戻れます。
- **架電結果を保存した瞬間に、その1件を元シートの同じ行へ書きます。** 退勤時・定期の反映も、これまでどおり動きます。
  - 行がずれていたら、電話番号・会社名で正しい行を探して書きます（空白を残しません）。
  - 同じ行にもう一度かけたら、最新の結果で上書きします。人が手で入力した値は、これまでどおり上書きしません。
  - 取り消したら、元シートのその行も、残っている最新の結果に戻します（無ければ、自分が書いた値だけを消します）。
  - 保存した瞬間の反映を止めたいときは、設定ブロックの `EXT_REALTIME` を `false` にします。

## ⑷ 前回勤務の続きから（日付・退勤をまたいでも）

- どの行まで架電したかを、サーバーの「リスト進捗」シートに持ちます（架電結果を保存した瞬間に更新）。
- **進捗は、管理者が「最初から」を押すか、別のリスト（別のタブ・別のスプレッドシート）を取り込むまで続きます。** 日付・退勤・端末が変わっても、続きからです。
- **管理者が「取込」を押しても、元シートが変わっていなければ何も変えません。** 「元シートに変更はありません」と表示します。
- 元シートに行が増えた・並びが変わったときの取込では、会社（電話番号・会社名）で突き合わせて、架電済みの印と位置を引き継ぎます。
- アポインターの「🔄 再同期」は、リストが同じなら位置を変えません。
- 端末は、出勤中は2分以内に、サーバーのリストが変わったことに自分で気づいて取り直します（通話中は、終わってから）。

### v109 のときに架電した行の引き継ぎ（導入した日に1回）

v109 は「取込を押すと、それより前の架電を未架電に戻す」決まりでした。v110 もこの決まりを引き継ぐため、**v109 で取込を押し直していた方は、それより前に架電した行が「未架電」になっています**（元シートには結果が入っています）。

- 管理者の画面の「🔗 元スプレッドシート連携の点検」→「元シートも開いて点検」を押すと、「元シートには結果が入っているのに、アプリでは未架電になっている行が N件あります」と出ます。
- **「元シートに合わせる（N件）」** を押すと、その行を架電済みにします。その方の画面には2分以内に反映され、結果が空の行から架電できます。
- 押さない場合、アプリはその行にも架電します（リストの最後まで進んだあとに、手前の未架電として戻ります）。
- 新しいリストを取り込むときも、元シートに結果が入っている行があれば、「架電済みにする」か「未架電のまま」かを選べます。
- 「最初から」を押したあとは、元シートに前回の結果が残っていても、すべての行にかけ直します。

## ⑸⑹ 藤田さんだけ、14〜18時が反映されない

### v109 で再現した仕組み

v108 で、件数はサーバーの「架電結果」から数えるようになりました。ただし、行の「日付・時刻・名前」は、端末が送った値のままでした。

1. ★ **端末のタイムゾーンが日本時間でない。** 14:05 の架電が「05:05」として記録され、14時の欄には出ません（9時より前の時刻として、9時の欄にまとまります）。
2. ★ **端末の時計がずれている。** 12時間ずれていると、午後の架電が午前の欄に入ります。
3. ★ **端末が送る名前が、名簿と少し違う**（空白入り・姓だけ）。その人の行に数えられません。
4. ★ **電波が悪い間の架電結果が届かない。** 5回の再送で「送信失敗」に回され、電波が戻っても自動では送られませんでした。その時間帯の件数が出ません。

⑹の「1時間ごと架電数」は、表の時間帯が 9〜17時で、18時台の架電を17時の欄に入れていました（コードで確認）。

### 修正

- **時刻はサーバーが決めます。** 端末が記録した瞬間（世界共通の時刻）を、サーバーの時計との差で補正し、日本時間に直して保存します。端末のタイムゾーンや時計がどうなっていても、正しい時間帯に入ります。
- **人は PIN で決めます。** 名前は名簿の表記に統一して保存します。これまでに保存された表記の違う行も、同じ人として数えます。
- **送信待ちの架電結果を捨てません。** 届くまで端末に残し、間隔を空けながら自動で送り続けます。v109 のときに「送信失敗」に回っていた記録も、アプリを開くと自動で送り直します（サーバーは同じ記録を二重に保存しません）。
- リアルタイム現況と「1時間ごと架電数」は、9〜18時を表示します。
- リアルタイム現況に、**端末の状態** を出します（未送信の件数・時計のずれ・古い版のアプリ・古いリスト）。

### 本番で原因を確かめる：📊 集計の点検

管理者の画面の「📊 集計の点検」で、人と日付を選んで「点検」を押します。

- サーバーに届いた件数と、時間帯ごとの件数（シートに書かれた時刻／記録した瞬間の時刻）を並べて出します。
- 「この端末は、時計かタイムゾーンが日本時間ではありませんでした」「名簿と違う表記の名前で届いた行があります」「端末に未送信が N件残っています」のように、見立てを文で出します。
- **v109 までに保存された記録にも使えます。** 藤田さんの過去の日付を点検すると、どれが起きていたかが分かります。
- 時刻がずれて保存されていた過去の行は、「N行を日本時間に直す」で直せます。もとの値は「端末の時刻」列に残します。
  - 直せるのは、端末の時計そのものは合っていて、タイムゾーンだけが違っていた場合です。

## ⑻ 通話録音の自動保存（Galaxy A25 → 指定のドライブのフォルダ）

保存先は、ご指定の https://drive.google.com/drive/folders/1P7MOlAg7gRR1X_imtjSjl81MmUUZFQ7V （設定ブロックの `REC_AUTOSAVE_FOLDER`）です。

### v109 までに起きていたこと

このフォルダは、v109 でも「録音の全体保管庫」として設定されていました。ただし、次の問題がありました。

- 端末からは「担当者ごとのフォルダ」へ送り、このフォルダへは複製していました。**複製に失敗しても、どこにも出ませんでした。**
- アプリから送った録音を、夜間の処理がもう一度複製し、同じ録音が2つ入ることがありました。
- PIN の先頭の 0 が記録で消え（091 → 91）、柏木さんの「きょう送った件数」が常に 0 でした。
- スマホやアプリを開き直すとフォルダの許可が外れ、そのまま気づかれずに止まっていました。

### v110 の動き

1. **端末から、このフォルダへ直接保存します。**
   - 場所：「年-月」→「日」のフォルダ（例：2026-11 → 11）
   - ファイル名：`氏名_年-月-日_時分秒_電話番号.m4a`（例：`藤田直美_2026-11-11_101530_0312345678.m4a`）
2. **いつ動くか**：アプリを開いている間、電話から戻るたび・3分ごと・出勤と退勤のときです。
3. **安全な移動**：ドライブ上で大きさが一致したことを確かめてから、スマホの元ファイルを消します。確かめられないものは消しません（v109 と同じ）。
4. **許可が外れたとき**：「出勤」を押したときに、フォルダの許可を取り直します。外れたままなら、ホームに「🔓 1回タップして自動保存を再開」を出します。
5. **フォルダに書けないとき**（共有が外れた等）：録音は「担当者ごとのフォルダ」へ保存して守り、管理者の画面に理由と直し方を出します。あとで自動の処理が、指定のフォルダへ写します。

### 準備（1回だけ）

- **フォルダの共有**：Google ドライブでこのフォルダを開き、「共有」→ GAS を動かしているアカウント（`hr.ashikaga@gmail.com`）を **編集者** として追加します。
  - 管理者の画面の「📁 録音の保存先」→「保存できるか確認」で確かめられます。
  - 保存したファイルの持ち主は、GAS を動かしているアカウントになります。
- **各アポインターの Galaxy A25**（取扱説明書 45ページ「通話を録音」）
  1. ホーム画面の「電話」→ 右上の「︙」→「設定」→「通話を録音」→「通話の自動録音」を ON（すべての通話）
     - 「保存先」が表示されるとき（SDカードを入れているとき）は、「内部ストレージ」を選びます。
     - 「1カ月以上前の録音ファイルを削除」は、ON のままで構いません。
  2. アプリのホームの「🎙 通話録音の自動保存」→「📂 録音フォルダをつなぐ」→「内部ストレージ」→「Recordings」→「Call」→「このフォルダを使用」→「許可」
  3. 「✅ 自動保存 ON」と出れば完了です。

### できないこと

- **アプリを閉じている間は保存されません。** 次に開いたときに、まとめて保存します（30日以内のもの）。
- Android でフォルダを読めるのは Chrome 132（2025年1月）以降です。Samsung Internet でアプリを入れた場合は、Chrome で開き直してください。
- フォルダの許可が毎回外れるかどうかは、端末の Chrome の動きによります。実機では確かめていません。

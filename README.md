# 川嶋メソッド テレアポ業務管理システム v70（架電システム × 経営システム 完全統合）

スキマグループ合同会社｜**本番URL**: https://sukima-group.github.io/teleapo/

## 🆕 v70：入力した瞬間に経営システムへ反映＋録音管理を統合

いただいた v67 一式に、**①即時反映（イベント駆動）**と**②通話録音の自動収集（別系統で開発していた機能）**を統合しました。**v67の全機能（経営連携・着地予測・異常検知・労務整合・DR）はそのまま維持**しています。

### ① 入力 → 経営システムへ「即時反映」
v67は**5分ごとの再集計（ポーリング）**だったため、アポインターが入力してから最大5分の遅れがありました。v70では**保存された瞬間に、該当する「日付×担当者」の1行だけを更新**します。

| きっかけ | 反映される内容 |
|---|---|
| 架電結果を保存 | 架電+1／接続+1（不在・不通以外）／アポ+1（アポのとき） |
| アポ報告を送信 | アポ+1 |
| 出勤・退勤・休憩の打刻 | 実働h（実測が入ると「推定」表示が外れる） |

- **O(1)の加算**なので、何百件保存されても重くなりません（行位置はキャッシュ、書込は LockService で保護）
- **5分ごとの全再計算はそのまま残しています**。万一ズレても次の再集計で自動的に直る二重構造です
- `kanriExport` に **`freshness`（最終反映時刻）** を追加。経営側が「いつ時点の数字か」を判断できます

### ② 通話録音の自動収集を統合
端末は**録音をメールで送るだけ**。管理者側が受信 → 担当者を判別 → **担当者別／年月／日**フォルダへ保存 → **電話番号＋時刻で架電記録に自動紐づけ**します。

- 📁 全員分のフォルダを自動作成＋本人Gmailへ自動共有／`_受信箱` も作成
- 📥 メール・受信箱から吸い上げ（二重保存の防止・取込ログ・担当者不明の可視化）
- ⏱ 毎日21時に自動実行、カバー率70%未満は管理者へメール通知
- 🎧 アポのみ／断りのみで絞り込んで▶再生、📊 録音カバレッジ
- **経営システムにも統合**：`kanriExport` の `recording` に担当者×日の**録音カバー率**を追加（`scope=recording` でも取得可）

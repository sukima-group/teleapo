最後の行が問題でした。v112 の ⑷ で足した「掛け直しの控え」（不在の先の架電回数）は、「架電結果」シートを、そのリストを取り込んだ日までさかのぼって読んで作ります。取り込んでから日が経っているリスト（田中さん 10/5・中村さん 9/28）では、これに 20〜30秒かかり、v112 はそれを同期の中で行っていました。管理者の画面の「不在のままの先」の集計も、人数分くり返し読んでいて、38〜67秒かかっていました。

v113 での変更：

- **同期（fetch_state）は、「架電結果」を読まない。** できあがっている控えがあれば返し、無ければ省きます。
- **控えは、アプリが同期のあとで、裏で取りに行く**（新しい要求 `recall_get`。10分に1回まで）。届くまでは、端末に控えてある前回の分と、端末の履歴で判断します。サーバーは、作った控えを 15分間使い回します（そのあとにかけた分は、アプリが端末の履歴から足します）。
- **管理者の画面の集計は、全員分を1回の読み取りで作る。** 架電ルールのカードは、設定を先に出し、集計はそのあとで届きます（集計を待たずに、設定を変えられます）。重い集計と設定シートの点検は、15分に1回まで（管理者の画面は5分ごとに自動で読み直しますが、そのたびには取りに行きません）。

v113 でも、**田中さん・中村さんの同期そのもの（控えを除いた部分）は 23〜35秒かかります。** これは v111 からの動きで、今回は変えていません（45秒の待ち時間に近いので、次に見直す候補です）。

## ⑴ 柏木さん（PIN 091）のリストが、別のリストになっていた原因

### 本番のシートと記録で確かめたこと

| 見たもの | 分かったこと |
|---|---|
| 「外部連携設定」シート | 柏木さんの行が 12行。22行目は PIN が文字の `091`（営業リスト／グルメ杵屋・1,966件）。23・24・26〜34行目は PIN が数字の `91` で、別のスプレッドシート（介護事業所・求人データ など）を指していた |
| 「監査ログ」シート | 11/11・11/17・11/18 に、柏木さんの取込が **1,966件 → 177件 → 258件** と、続けて記録されていた（1回の「取込」で、別々のリストが順に取り込まれ、最後のものが残った） |
| コード（v111） | 管理者の画面の表示と保存は「その PIN の先頭の行」。取込・同期は「シートの全部の行」。PIN `91` と `091` は同じ人として扱う。この食い違いが原因 |

同じ症状を、模擬のサーバーで再現できました（v111：取込が7回走り、最後に成功した別のリストが残る。田中さんの取込は止まる／v112：取込は1回・設定したリスト・田中さんも取り込める）。

### v112 で変えたこと

- **連携設定は「1人に1行」として読みます。** 同じ人の行が複数あるときは、先頭の行（＝管理者の画面に出ている行）だけを使います。取込・同期・点検のすべてが、同じ1行を見ます。
- **余分な行は、消さずに「外部連携設定_退避」シートへ移します**（管理者の画面を開いたとき・連携の操作の前・夜間の処理・`v112SetupCheck`）。移した行数と人は、管理者の画面の「🧹 設定シートの整理」と監査ログに出ます。もとのシートでは、その行が **空の行** になります（行は詰めません。行を詰めると、同じ瞬間に動いているほかの保存が、ずれた行＝別の人の行に書くおそれがあるためです。空の行は、どの処理も読み飛ばします）。
- **名簿にいない PIN の行は、「全員の取込・同期」では飛ばします**（削除したアカウントの行が残っていても、動きません）。
- タブの番号（gid）が `0` のタブを指定できない不具合を直しました（`0` が「未指定」として扱われていました）。
- **同じ原因の不具合が、ほかの設定にもありました。** 録音設定（録音フォルダなど）と KPI 目標は、「読むのは最後の行・書くのは先頭の行」になっていて、0 で始まる PIN の人は、保存した内容が反映されないことがありました。読む行と書く行をそろえました。「暗証番号」「架電位置」のシートに残っている古い行は、数だけを管理者の画面に出し、「余分な N行を、退避シートへ移す」を押したときにだけ片付けます（そのままでも動きます）。

## ⑵ 会社スケジュール（休業・行事）

管理者の画面 →「🗓 会社スケジュール・SV不在」→「＋ 休業・行事を登録」。

| 種別 | 動き |
|---|---|
| **休業**（会社が休み） | 「この期間は、シフト（出勤）を登録できないようにする」が、はじめから入っています。期間は、年をまたいで指定できます（例：2026-12-24 〜 2027-01-05。最長 366日） |
| **行事・お知らせ** | アポインターの画面に出すだけです（シフトは登録できます）。チェックを入れれば、休業と同じく登録できない日にできます |

休業を登録すると：

- **シフトのカレンダー**：その日は斜線と「休業」の表示になり、押しても時間の入力は開きません（「12/24（木）は会社の休業日（冬期休暇）です。シフトは登録できません」と出ます）。一括テンプレでも入りません。入力の途中だった出勤は、入力から外します。
- **ホーム**：45日前から「12/24（木）〜1/5（火）は 冬期休暇（会社の休業）です。この期間は、シフトを登録できません」と出ます。当日は「本日は会社の休業日です」。
- **サーバー**：申請に休業日の出勤が入っていても、その日を「休み」として保存し、本人の画面と管理者へのメールに、その旨を出します（古い版の画面・送信待ちの申請への備えです）。
- **すでに出勤を登録している人がいるとき**：管理者の画面に「⚠ 『冬期休暇』の期間に、出勤が登録されています」と、名前・日・承認の状態が出ます。「この出勤を、休みに直す（本人へメール）」を押すと、その日だけを休みに変えます（ほかの日・承認の状態は変えません）。本人が直すこともできます（シフト画面に知らせが出て、「修正申請」で休みになります）。
- **取消**：「取消」を押すと、アポインターの画面から消え、その期間のシフトも登録できるようになります。

登録した内容は、メインのスプレッドシートの「会社スケジュール」シートに入ります（取り消した予定も、状態が「取消」になって残ります）。

## ⑶ SV不在

管理者の画面 →「🗓 会社スケジュール・SV不在」→「＋ SV不在を登録」。

- **不在にする人**：はじめは、面談の相手に登録されている SV の名前が入っています（書き換えられます）。
- **期間**：「いまから1時間／2時間／3時間／いまから本日いっぱい／明日 終日」のボタンで入ります。日付と時刻を、手で入れることもできます（時刻が空なら、終日）。
- **急ぎのときの連絡先・ひとこと**：入れると、アポインターの画面に出ます（例：「急ぎは山口課長へ電話」）。

アポインターの画面：

| いつ | 出るもの |
|---|---|
| 不在の間 | ホームの先頭に「🔕 SV（◯◯さん）は、いま不在です　12:00 まで／この間、**LINE の返事はすぐに来ません**。返事を待たずに、架電を続けてください。」と、連絡先・ひとこと。通話の画面の先頭にも1行 |
| 始まる24時間前から | ホームに「📌 本日 15:00〜16:30 は、SV（◯◯さん）が不在の予定です。LINE の返事はすぐに来ません。」 |
| 終わりの時刻・「戻った（解除）」のあと | 消えます（終わりの時刻は、サーバーに聞かなくても端末が自分で消します） |

届くまでの時間：出勤中の端末は、2分ごとの通信（稼働状況の送信）の返事で届きます。出勤前の端末は、ログイン・同期のときと、5分ごとの確認で届きます。入力の途中（結果の入力・アポ取得報告・確認の画面）は、画面を描き直しません。

管理者の画面には、「🔕 いま、SV（◯◯）は不在です。アポインターの画面に『LINE の返事はすぐに来ません』と出ています」と出るので、解除し忘れに気づけます。

## ⑷ 架電ルール（不在の先への掛け直し）

管理者の画面 →「🔁 架電ルール（不在の先への掛け直し）」。

| 設定 | はじめの値 | 意味 |
|---|---|---|
| ルールを使う | 使う | 外すと、v111 と同じ（不在だった先すべてに掛け直せる） |
| 1社にかける回数の上限 | 3回 | そのリスト（いまの周回）で、その会社にかけた回数。上限に達した先は、もう出しません |
| 前の電話からあける時間 | 20時間（翌日から） | 最後にかけてから、この時間がたつまでは出しません |

- アポインターの画面は、リストを最後までかけたあとの「🔁 不在だった N件に、もう一度かける」の **N が「いま掛け直せる先」だけ** になります。その下に、「まだ間隔があいていない ◯件（いちばん早い先は 11/21（土）05:30 から）」「3回かけて不在だった ◯件（これ以上はかけません）」と出ます。
- **回数と時刻は、サーバーの架電結果から数えます。** 端末の履歴（直近 1,000件）より前の不在・ほかの端末でかけた分も入ります。端末を替えても、同じ結果になります。
- 管理者の画面には、人ごとの「不在のままの先」（いま掛け直せる・間隔待ち・上限）が出ます。
- ルールを変えると、出勤中の端末には2分以内に反映されます。
- 対象は、元スプレッドシートとつないだリストです。「再架電」（日時を決めた掛け直し）は、これまでどおり、決めた日時にお知らせします（このルールの対象外）。「断り」「不通」「アポ獲得」の先は、これまでどおり掛け直しの対象になりません。

## 調べた設計と、当てはめた結果

**先にお断り**：調べたのは、コールセンター向けの発信システム（Bright Pattern・Genesys Cloud・VICIdial・Convoso）の、公開されている管理者向けの説明書と解説です。国内のテレアポ会社が社内で使っている設定の中身は、公開されている情報では確かめられませんでした。国内の製品は、比較記事で機能の一覧を確かめています（出典は末尾）。

どの製品も、発信の進め方を、次の部品に分けて持っていました。この仕組みに当てはめると、こうなります。

| コールセンターの発信システムの部品 | この仕組みでは | v112 |
|---|---|---|
| リストと案件（キャンペーン） | 元スプレッドシート連携・リスト台帳・案件名（v110・v111） | 連携設定を「1人に1行」に（⑴） |
| 通話結果（ディスポジション）ごとの扱い：終わり／掛け直し／コールバック／発信禁止 | アポ獲得・断り＝終わり、再架電＝日時を決めたコールバック、不通が続いた番号＝NG リスト（v111） | **不在＝ルールにしたがって掛け直し**（⑷） |
| 掛け直しのルール：1件あたりの回数の上限・結果ごとの間隔 | v111 までは無し（不在の先すべてに、いつでも掛け直せた） | **回数の上限・前の電話からの間隔**（⑷） |
| リストの一巡（ダイヤリング・パス）：一巡のあと、終わっていない先だけをもう一巡 | 「不在だった先に、もう一度かける」（v110） | 一巡の対象を、ルールで決める |
| 回数の数え方：システムが1か所で数える | v111 までは、端末の履歴（直近 1,000件）で数えていた | **サーバーの架電結果から数える**（再現性） |
| カレンダー・営業時間 | シフト申請（8:00〜22:00・15分刻み） | **会社スケジュール（休業はシフト登録不可）**（⑵） |
| オペレーターの状態と、管理者の見える化 | 出勤・休憩・退勤、稼働状況、KPI、録音（v110・v111） | **SV の在・不在を、全員の画面に出す**（⑶）／掛け直しの見通し |
| 発信の速さ（プレビュー／プログレッシブ／予測発信） | 人が1件ずつ確かめて発信（プレビューに当たる）・オートコール（連続発信） | 変更なし |

調べて分かったことのうち、設計に効いた点：

- Bright Pattern は、掛け直しを「通話結果 → 次の動き」の対応表（ダイヤルルール）として持ち、1件あたりの回数の上限は別の設定にしています。v112 も、「不在」に対する動き（間隔）と、回数の上限を分けました。
- Genesys Cloud は、不在・話中などへの自動の掛け直し（リコール）を、人が1件ずつ確かめて発信する方式（プレビュー）では使えないとしています。この仕組みもプレビューに当たるので、**自動で掛け直すのではなく、アポインターが「もう一度かける」を押したときに、ルールに合う先だけを出す** 作りにしました。
- VICIdial と Convoso は、結果ごとに「次にかけられるまでの時間」と「回数の上限」の2つを決めます。v112 の設定も、この2つだけにしました。

**入れていないもの**

| 部品 | 入れていない理由 |
|---|---|
| 番号ごと・1日あたりの回数の上限 | 1社に1番号で、人が1件ずつ発信するため、1社あたりの上限で足ります |
| 予測発信・複数回線への同時発信・通話のモニタリング | 電話回線の側のシステム（CTI）の機能で、スマホの電話アプリで発信するこの仕組みでは作れません（v111 の README と同じ） |
| 自動の掛け直し（時刻が来たら、勝手に発信の列に入る） | 上の Genesys の点のとおり。元シートの順番どおりにかける v110 の考え方とも合いません |

**次の候補**（調べた製品にあり、この仕組みにまだ無いもの。今回は入れていません）

1. 架電できる時間帯（案件ごと。昼休み・終業後を避ける）と、その外で発信しようとしたときの知らせ
2. 不在の先を、「前回と違う時間帯」のものから先に出す
3. 再架電（コールバック）の、予定の時刻を過ぎた件数を、管理者の画面に出す

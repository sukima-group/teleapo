### ⑵ Zoom Phone（条件２）

管理者の画面で「Zoom Phone で発信：使う」にすると（v115 と同じ）、アポインターの画面に「発信のアプリ（この端末）：📱 電話／🟦 Zoom Phone」が出ます。「🟦 Zoom Phone」を選んだときの発信は、次のとおりです。

| 端末 | 発信 |
|---|---|
| PC（Windows・Mac） | 発信ボタンで Zoom のアプリが開き、そのまま発信します（v115 と同じ） |
| **iPhone** | **v116 から、発信ボタンで Zoom のアプリが開き、そのまま発信します**（`zoomphonecall://+81…`）。番号のコピーはしません。Zoom のアプリを入れて、Zoom Phone の番号でログインしておきます |
| Android | 番号をコピーして、Zoom のアプリを開きます（v115 と同じ）。Zoom の「電話」で、番号の欄に貼り付けて発信します |

- **Android を直接発信にできない理由**：Zoom の説明書で、Android はほかのアプリからの発信（`zoomphonecall`・`tel`）に対応していないとされています。Zoom のアプリは Android の「電話アプリ」として登録されないため、既定の電話アプリにもできません（Zoom コミュニティの回答）。
- **iPhone（iOS 18.2 以降）の別の方法**：iPhone の「設定」→「アプリ」→「デフォルトのApp」→「通話」で Zoom を選ぶと、電話番号のリンクも Zoom で開くようになります。Zoom コミュニティでは、Zoom Phone の有料のライセンスが要ると回答されています。この設定にすると、アプリの「📱 電話」で発信しても Zoom から発信されます。
- 架電結果は、これまでどおりアプリで入力します。v115 の「Zoom の通話履歴の取り込み」（通話秒・結果を架電結果の行に書く）は、そのまま使えます。

- **期限超過の一覧**：予定の時刻を過ぎて、まだかけていない予定（古い順に20件。名前・会社・予定・何時間過ぎたか・メモ）。

  1. 予定を入れた5分後より後に、同じ人がその番号へかけていれば「完了」（完了のしかた：「架電：断り（あとから確認）」など。架電結果シートで確かめます）

## 調べた設計と、当てはめた結果

**先にお断り**：調べたのは、発信システム（Genesys・Avaya・Mindful）と Zoom・Apple の、公開されている説明書・解説・コミュニティの回答です。国内のテレアポ会社が社内で使っている設定の中身は、公開されている情報では確かめられませんでした（出典は末尾）。

| 発信システムの部品 | 調べて分かったこと | この仕組みへの当てはめ（v116） |
|---|---|---|
| **担当者が持つ予定**（エージェント・オウンド・コールバック） | Genesys Cloud では、予定を入れた担当者が予定を持ち、持つ期間（1時間〜30日）と、期間が過ぎたらキューへ回すかを管理者が決めます。持つ期間の上限は、2026年4月に7日から30日へ延びました | 予定に入れた人の PIN を付け、その人がかけたら完了。7日で期限切れ |
| **置き換え・期限切れ** | Avaya の発信システム（POM）は、同じ相手に新しい予定を入れると古い予定を「Overwritten（置き換え）」にし、期限が来た予定は「Expired（期限切れ）」にして、担当者に出しません | 「置き換え」「期限切れ」の状態 |
| **時間どおりの率** | Mindful のコールバックの報告書は、約束した時刻の前後の幅の中でかけられたかを「Punctuality（時間どおり）」として数えます | 予定の15分前〜60分後にかけたら「時間どおり」 |
| **管理者の報告** | Genesys の報告書（Campaign Callbacks Summary）は、予定・完了・逃した数を日ごとに出し、予定を入れた本人が完了した数（personal callbacks）を分けて数えます | 担当者ごとの表（直近30日）と、期限超過の一覧 |
| **電話（CTI）との連携** | Zoom の説明書：iPhone は `zoomphonecall` に対応（発信者番号などの一部の指定は使えない）、Android は `zoomphonecall`・`tel` に対応しない。Apple：iOS 18.2 から、既定の通話アプリを選べる。Zoom の Smart Embed：ウェブのアプリの中に Zoom Phone を埋め込み、発信・通話の終わりの知らせを受け取れる | iPhone は Zoom から直接発信（⑵）。Smart Embed は次の候補 |

**再現性のための作り**

- 予定の状態（未対応・完了・置き換え・期限切れ）と、完了のしかたは、サーバーが決めてシートに残します。どの端末で見ても同じです。
- 自動で完了にする決まり（入れた人が・その番号に・予定を入れた通話より後にかける）は、サーバーと端末で同じです。
- 古い予定の整理は、まず数えるだけ（下見）→ 整理、の2段階です。監査ログに残ります。

**入れていないもの**

| 部品 | 入れていない理由 |
|---|---|
| 予定の時刻に、システムが自動で発信する | スマホの電話・Zoom のアプリで発信する仕組みのため。予定の時刻にお知らせを出し、「📞 今すぐ発信」の1回で発信します |
| 期限が来た予定を、ほかの人に回す | 予定は入れた本人がかける約束のため。管理者が期限超過の一覧を見て判断します |
| 時間帯ごとの予定の数の上限 | 一人ひとりの予定で、混み合う窓口がないため |
| Zoom Phone の Smart Embed（PC の画面の中で発信） | Zoom の管理者が、Zoom Marketplace で Smart Embed を入れ、このアプリの URL（`https://sukima-group.github.io`）を許可する設定が要るためです。開発者の掲示板には、発信の命令（`zp-make-call`）で発信されないという報告が 2024〜2026年にあり、本物の Zoom のアカウントで確かめてから入れるのが安全です |

**次の候補**（今回は入れていません）

1. Zoom Phone の Smart Embed（PC）：アプリの中で発信し、通話が終わったら結果の入力を自動で開く（Zoom の管理者の設定が要ります）
2. 期限超過の再架電を、ホームの「次にかける」に先に出す（いまはお知らせと一覧）
3. 接続率を、曜日ごと・案件ごとにも出す（v115 の候補の3）

## ⑴ 通話録音の自動保存（Galaxy A25 → 指定のドライブのフォルダ）

保存先は、ご指定のフォルダ（設定ブロックの `REC_AUTOSAVE_FOLDER`）です。フォルダの URL は、公開しているこのリポジトリには載せていません。

- 場所とファイル名は、v110 と同じです：「年-月」→「日」のフォルダに、`氏名_年-月-日_時分秒_電話番号.m4a`（例：`藤田直美_2026-11-15_101530_0312345678.m4a`）。
- **以前の保存先（A アポインター毎日の架電音声）の録音は、動かしません・消しません。** 架電記録との紐づけには、以前の保存先の録音も引き続き使います。

### はじめの設定（1人1回・約2分）

まだ録音フォルダをつないでいないスマホでアプリを開くと、自動で開きます（1日1回まで。通話や入力の途中には開きません）。「出勤」を押したときも、未設定なら案内します。「あとで設定する」を押すと、その日は出ません。次の日に、もう一度出ます。

1. **スマホの設定**：電話アプリ → 右上の「︙」→「設定」→「通話を録音」→「通話の自動録音」を ON（すべての通話）。
   - 「保存先」が出るとき（SDカードを入れているとき）は、「内部ストレージ」を選びます。
2. **フォルダをつなぐ**：「📂 録音フォルダをつなぐ」→「内部ストレージ」→「Recordings」→「Call」→「このフォルダを使用」→「許可」。
3. **確認**：アプリが、つないだフォルダの録音を確かめます。
   - **新しい録音（7日以内）があれば**「✅ 自動録音は働いています」と出て、完了です。
   - 録音が古いものだけのとき・録音が見つからない知らせが出ているときは、「働いています」とは出しません。「自分の携帯などに1回かけて10秒ほど話す →『もう一度確かめる』」と案内します。
   - 録音が1件も無いときも、同じ案内です。それでも出ないときは、①が OFF か、つないだフォルダが「Call」ではない、と案内します。

ホームの「🎙 通話録音の自動保存」のカードからも、いつでも開けます（「🎙 はじめの設定を始める」）。いつも①から始まり、フォルダをつないであるスマホでは、①のあと③へ進みます。v110 でつないである端末は、そのまま使えます（保存先だけが新しいフォルダに変わります）。

### 設定のあと（自動）

- アプリを開いている間、電話から戻るたび・3分ごと・出勤と退勤のときに、新しい録音をドライブへ保存します。ドライブで大きさが一致したことを確かめてから、スマホの元ファイルを消します（v110 と同じ）。
- **録音が止まったときの知らせ**：相手と話した通話（結果が「不在」「不通」以外で、電話アプリに45秒以上いた通話）なのに、電話から戻って2分たっても、その時間の録音が見つからないことが2件続くと、ホームに「⚠️ 通話が録音されていないようです」と出します（「確かめ方を見る」で、はじめの設定が開きます）。管理者の画面の「🎙 通話録音の自動送信」にも、その人の行に赤い字で出ます。録音ができるようになると、自動で消えます。
- フォルダの許可が外れたとき・保存先に書けないときの動きは、v110 と同じです（「出勤」で許可を取り直す／担当者ごとのフォルダへ保存して守り、管理者の画面に理由と直し方を出す）。

### できないこと

- スマホの「通話の自動録音」を、アプリから ON にすること。
- アプリを閉じている間の保存（次に開いたときに、30日以内のものをまとめて保存します）。
- Android でフォルダを読めるのは Chrome 132（2025年1月）以降です。Samsung Internet でアプリを入れた場合は、Chrome で開き直してください。

## ⑵ アポイント台帳（商談日の順に自動登録）

登録先は、ご指定のスプレッドシート（設定ブロックの `APPO_LEDGER`）です。URL は、公開しているこのリポジトリには載せていません。

### 考え方

台帳は、人が見て・直して使う表です。アプリが台帳に書くのは、次のことだけにしました。

| すること | しないこと |
|---|---|
| 新しいアポを、商談日 → 商談時間の順の位置に、1行足す | 表全体の並べ替え（管理者が押したときだけ行います） |
| 登録済みの行に、録音のリンクを足す（「録音」のセルが空のときだけ） | 人が直した・空にしたセルの書き戻し |
| アプリで取消にしたアポの「状態」を「取消」にする（空か「予定」のときだけ） | 人が入れた「状態」（成約 など）の書き換え |
| 足りない列を、最初の1回だけ、右端に足す | 人が消した列の足し直し（「アポID」の列を除く） |

### 動き

1. アポインターがアポ取得報告を送ると、サーバーが「アポイント」シート（これまでどおり）に保存し、**その場で** 台帳へ1行を足します。
2. 足す位置は、**商談日 → 商談時間の早い順の位置** です（その日時より前の商談の行の、すぐ下）。区切りの行（「―― 12月 ――」など）や合計の行は、動かしません。表の下にあらかじめ用意した行（チェックボックスなど）があるときは、用意した行の上から順に使います。
3. 新しい行の「状態」には「予定」を入れます（商談日が過ぎている分を入れたときは、空のままです。結果は人が入れます）。
4. 結果は、「アポイント」シートの「台帳」列に残ります。
   - 「済 月/日 時:分」＝台帳に登録済み
   - 「未」＝まだ登録できていない（その夜の自動処理が登録します）
   - 「保留」＝名簿にない PIN から届いた報告（自動では入れません）

### 台帳の列

- **空のシート**には、次の見出しを作ります。
  商談日・商談時間・曜日・案件名・法人名・担当者・役職・電話番号・メール・住所・外国人の採用も候補・特定技能案件・外国人雇用・特定技能・技人国・面接・採用決定者・人柄・引き継ぎメモ・アポ取得者・アポ取得日・録音・状態・アポID
- **すでに見出しがあるシート**では、1〜10行目から見出しの行を探し（「商談日」と「法人名」があれば見出しと判断します）、**その並びに合わせて** 書きます。
  - 「会社名」「訪問日」「TEL」「先方担当者」などの言い方も読みます。「（必須）」「※必須」などの注記は、読み飛ばします。
  - 同じ項目に当たる見出しが2つあるとき（「商談日」と「訪問日」、「先方担当者」と「担当者」など）は、「商談日」「先方担当者」の列を使います。
  - **どの列を何として読んでいるかは、管理者の画面に出ます**（例：「列の読み取り（2行目の見出し）：商談日＝C列「商談日」／法人名＝E列「会社名」…」）。違っていたら、台帳の見出しを直してください。
  - 足りない列は、最初の登録のときに、右端に足します。台帳で消した列は、足し直しません（「アポID」の列だけは置き直します）。表題の行や、人が使っている列は変えません。
- **台帳として読める見出しが無いシート**（別の内容が入っているシート）には書きません。同じスプレッドシートに「アポイント台帳」タブを作って登録し、管理者の画面に理由を出します。

### 人が直した内容は、書き戻しません

- 登録済みの行に足すのは、**録音のリンクだけ** です。台帳で直した商談日（リスケ）・状態・担当者名も、空にしたセルも、そのままです。
- 手で入力済みの行（アポID が空の行）に、法人名＋商談日＋商談時間が同じ報告が届いたときは、行を増やさず、その行の空のセルを埋めます（最初の1回だけ。入力済みのセルは変えません）。
- 台帳で商談日を直したとき：行の位置は、そのままです。管理者の画面に「商談日の順になっていない行が N か所あります」と出ます。「曜日」は、アプリが書いた1文字の曜日のセルに限り、夜間の処理か「台帳をそろえる」のときに、直した日付に合わせます。
- 台帳で消した行は、戻しません（管理者の画面に「台帳で消した N件も入れ直す」が出るので、戻したいときだけ押します）。
- アプリで取消にしたアポは、台帳に入れません。すでに台帳にあるときは、「状態」が空か「予定」のときだけ「取消」にします。
- 同じアポは1行です。アポID で見分け、アポID が違っても、法人名＋商談日＋商談時間が同じ報告は、同じアポとして扱います。同じ報告がもう一度届いても、すでにある行は書き換えません。

### 台帳に書けなかったとき

どの場合も、**アポ取得報告そのものは「アポイント」シートに保存します。**

| 場合 | 動き |
|---|---|
| 台帳を開けない（共有されていない） | 「台帳」列は「未」。管理者の画面に、理由と直し方（共有する相手）を出します。共有を直すと、その夜の自動処理が入れます。すぐ入れるときは「台帳に入れ直す」 |
| ほかの処理が書き込み中（報告が同時に届いたときなど） | 台帳には書かず、「未」にします（2つの処理が同時に書いて、行がずれるのを防ぐためです）。その夜の自動処理が、商談日の位置に入れます。すぐ入れるときは、管理者の画面の「いますぐ入れる」 |
| 入力規則（プルダウン）や保護で、書けない列がある | その列だけを飛ばして、ほかの列を書きます。1セルも書けないときは、行を足さず、「未」にします |
| 名簿にない PIN から届いた報告 | 「保留」。管理者の画面に件数が出ます。確かめて「台帳に入れる」を押したときだけ入れます |

夜間の自動処理が台帳に足すのは、1晩に40件までです（残りは次の夜）。

### 管理者の画面「📅 アポイント台帳」

- **画面を開くだけでは、台帳に何も書きません**（見出しや列を作るのは、登録のときです）。
- 出る内容：台帳に書き込めるか・登録の件数・列の読み取り・次の登録のときに右端に足す列・**今日と明日の商談（前日確認用）**・確認項目が YES でない報告の件数・台帳に書けなかったアポの件数・自動では入れていないアポの件数。
- 「台帳をそろえる（録音のリンク・並べ直し）」：確かめの画面が出ます。録音のリンクを入れ、**表全体を** 商談日の順に並べ直します。
  - **区切りの行や合計の行がある表では、それらの行も動きます。** そのような表では、押さないでください（新しいアポは、押さなくても商談日の位置に入ります）。
  - フィルタがかかっていて並べ替えられないときは、理由を出します（台帳の内容は変えません）。
  - 録音のリンクは、録音が架電記録に紐づいたあと（毎晩の処理）で入ります。毎晩の自動処理が探すのは、直近14日のアポです。それより前のアポには、「台帳をそろえる」を押すと入ります（120日前まで）。
- 「夜間のメールに『明日の商談』」：毎晩の報告メールに、明日の商談の一覧を足します（ON／OFF）。
- 「台帳に入れる（N件）」：**v110 までに届いたアポ** と、**名簿にない PIN から届いた報告** を、台帳に入れます（確かめの画面が出ます。入れたあと、表全体を商談日の順に並べ直します。取消にしたアポは入れません）。

## ⑶ 架電リストへの記録と、架電報告書（PDF）

### 元シートの各社の行に、かけた日時と結果を残す

v110 までは、元シートの行に「最新の結果」だけを書いていました（2回目にかけると、1回目の日時と結果は元シートから消えていました）。v111 は、見出し「架電回数（自動）」「架電履歴（自動）」の列に、その会社にかけたすべての電話を残します。

```
架電回数（自動）：2
架電履歴（自動）：1回目 2026/11/05 10:15 不在
　　　　　　　　　2回目 2026/11/07 14:02 アポ獲得
```

- 架電結果を保存した瞬間に書きます。退勤時・定期の反映でも、同じ内容になります（何度書いても増えません）。
- 列は、**見出しの名前で探します**。元シートに列を足したり入れ替えたりしても、別の列には書きません。列が無ければ、見出しの右端に足します。
- **元シートにもとからある「架電回数」「架電履歴」などの列（お客様や担当者が手で付けている列）は、使いません・書き換えません。** アプリが使うのは、「（自動）」まで同じ名前の列だけです。
- 取り消すと、その1件だけが消えます。「N回目 年/月/日 時:分 結果」の形の行だけを、アプリが書いた行として扱います。人が同じセルに書き足したメモ（日付で始まるメモも）は、消しません。
- v110 のときにかけた電話も、次の反映（退勤時・定期・管理者の「反映」）で入ります（いまのリストでかけた分）。
- あわせて、翌日以降にかけ直したとき、元シートの「結果」の列がその場で最新になるようにしました（v110 は、退勤時の反映まで前の日の結果のままでした）。

### 案件・リスト

- 取込のたびに、リストを「リスト台帳」シートに控え、**案件名** を付けます。案件マスタの名前・別名が元スプレッドシートの名前に入っていればその案件、無ければ元スプレッドシートの名前（「_架電リスト」などの後ろは除きます）を案件名にします。
- 案件名は、管理者の画面の「📄 架電報告書」→「▼ リストと案件名」で直せます。同じ案件名のリストは、同じ案件としてまとまります。
- アポインターの架電カードに「📁 案件：◯◯」と出ます。アポ取得報告の案件名にも、自動で入ります。

### 管理者の画面「📄 架電報告書」

- **ご指定の台帳・フォルダの実物**：中身を見られなかったため、台帳のいまの見出しで正しく読めるかは、導入手順の5と8で確かめてください。結合したセル・保護した範囲・条件付き書式など、表の作りによる違いは、模擬では確かめきれていません。
- **実機の Galaxy A25**：はじめの設定の画面の進み方（電話アプリの設定の文言・フォルダの選択画面）、フォルダの許可が保たれるかどうか、録音ができた時刻の読み取り（録音が止まったときの知らせは、録音ファイルの更新時刻で判断します）。
- **スマホでの印刷**：報告書の「🖨 印刷／PDFに保存」は、PC の Chrome で確かめました。スマホで印刷の画面が出ないときは、「↗ 別のタブで開く」から印刷してください。
- **v109 から直接 v111 へ上げる場合**：受け取った ZIP に v109 のファイルが無いため、確かめていません（v110 → v111 の載せ替えは確かめています）。
- **v109 までのテスト**（シフト申請・管理者の認証・収支・銀行明細）：v110 のときと同じ理由で、再実行していません。これらの処理は変えていません。

もう1つ、仕組みの上の限りがあります。アポインターの本人確認は、これまでどおり3桁の PIN だけです。「名簿にない PIN は保留」は軽い備えで、名簿にある PIN を名乗った報告は、そのまま台帳に入ります。

## ⚠️ 導入手順

1. **控えを取る**：メイン・管理者用のスプレッドシートと、**アポイント台帳のスプレッドシート** で、ファイル → 版の履歴 → 今の版に名前を付けます。
2. **共有する（2か所）**：次の2つを開き、「共有」→ `hr.ashikaga@gmail.com` を **編集者** として追加します（すでにそのアカウントの持ち物なら、不要です）。
   - 録音のフォルダ（設定ブロックの `REC_AUTOSAVE_FOLDER`）。あわせて、フォルダの「一般的なアクセス」を「制限付き」にしてください
   - アポイント台帳（設定ブロックの `APPO_LEDGER.SHEET_ID`）
3. **GAS**：「コード.gs」を全消去 → `gas-code.txt` を貼り付け → 保存。
4. **GAS**：デプロイ → デプロイを管理 → ✏️編集 → バージョン「**新バージョン**」→ デプロイ。URL は変わりません。
   - 忘れると古い版が動き続け、全員の画面に赤い帯が出ます。
5. **GAS**：エディタで `v111SetupCheck` を実行します。権限の確認が出たら「許可」します。**この確認は、台帳に見出し（空のとき）と足りない列（右端）を作ります。アポの行は足しません。** ログで次を確かめます。
   - ① 録音の自動保存先：フォルダの名前と「保存できます」（「開けません」のときは、手順2）
   - ② アポイント台帳：「◯◯／シート名 に書き込めます」と件数（「⚠」のときは、手順2。「◯◯タブを使います」と出たときは、下の「台帳のタブ」）
     - **「列の読み取り: 商談日＝◯列「…」／法人名＝◯列「…」…」が、実際の台帳と合っていること。** 違っていたら、台帳の見出しを直して、もう一度実行します。
     - 「足した列：…」に出た列のうち、要らないものは、台帳で列ごと消して構いません（「アポID」は残してください）。
   - ③ リスト台帳：いまのリストと案件名
   - ④ 元シートの「架電回数（自動）」「架電履歴（自動）」の列：書きます
   - ⑤ 架電報告書：フォルダと「PDF への変換：できます」
   - ⑥ サーバーの版：v111　⑦ 自己点検：すべて合格
6. **GitHub**：`index.html`・`sw.js`・`README.md` を上書きして Commit します。
   - **tests フォルダは上げないでください。** `gas-code.txt` は上げなくても動きます（GAS に貼るだけ）。
7. **全端末・PC**：アプリを開き「🔄 最新の状態に更新」を押します。
8. **管理者の画面の先頭** で確かめます。
   - 赤い帯が出ていないこと（出ていれば手順4）。
   - 「📅 アポイント台帳」：「◯◯／シート名」と件数、「列の読み取り」が出ていること。「台帳を開く ↗」で、ご指定の台帳が開くこと。
     - 赤い字で「開けません」と出たら、手順2。
     - 「…には、台帳として読める見出しがありません。そのタブには書かず、『アポイント台帳』タブに登録します」と出たら、下の「台帳のタブ」。
     - 「自動では台帳に入れていないアポが N件あります」は、入れるときだけ「台帳に入れる」を押します。
   - 「📁 録音の保存先」→「保存できるか確認」。
   - 「📄 架電報告書」→「▼ リストと案件名」で、案件名を確かめます（違っていれば直して「案件名を保存」）。
9. **最初のアポ取得報告のあと**：台帳に1行入り、商談日の順の位置に入っていることを確かめます。入っていないときは、管理者の画面の「📅 アポイント台帳」に理由が出ます（報告そのものは「アポイント」シートに保存されています）。
   - 確認のためだけの「テストのアポ」は、おすすめしません（架電結果・KPI・元シートにも記録が残るためです）。
10. **各アポインターの Galaxy A25**：アプリを開くと「はじめの設定」が出ます。①→②→③と進め、「✅ 自動録音は働いています」を確かめます（v110 でつないである端末は、そのまま使えます。確かめたいときは、ホームの「🎙 通話録音の自動保存」のカードから開けます）。
11. **月末・報告のとき**：管理者の画面の「📄 架電報告書」で、期間と案件を選んで作り、「👁 開く」→「🖨 印刷／PDFに保存」。

v109 から直接上げる場合は、v110 の README の導入手順（`adminSetupCheck` → `v110SetupCheck`、「元シートも開いて点検」）も行ってください。

### 台帳のタブ

台帳のスプレッドシートの最初のタブ（URL の `gid=0`）に、すでに別の内容が入っていて、「商談日」と「法人名（会社名）」の見出しが見つからないときは、そのタブには書かず、「アポイント台帳」タブを作って登録します。もとのタブに登録したいときは、次のどちらかです。

- もとのタブの見出しの行（1〜10行目のどこか）に、「商談日」と「法人名」の列を作る。
- 別のタブに登録したいときは、`gas-code.txt` の設定ブロックの `APPO_LEDGER.GID` を、そのタブの番号（URL の `#gid=` のあとの数字）に変える。

### 自動で追加されるもの（既存のデータは消しません）

| 場所 | 追加 |
|---|---|
| メイン | 「リスト台帳」シート、「報告書ログ」シート（最初に報告書を保存したとき） |
| メイン「アポイント」 | 列：アポID・PIN・受信日時・リストID・架電CID・引き継ぎメモ・外国人の採用も候補・台帳（右端に追加。既存の20列は動かしません） |
| アポイント台帳 | 空なら見出し。足りない列（最初の1回だけ・右端）。新しいアポの行。読める見出しが無いときは「アポイント台帳」タブ |
| 各アポインターの元シート | 列：架電回数（自動）・架電履歴（自動）（見出しの右端） |
| ドライブ | 新しい録音のフォルダの下に「年-月」→「日」。報告書を保存したときに「川嶋メソッド_架電報告書」→「年-月」 |
| スクリプトプロパティ | 台帳の最後の登録・台帳に足したことのある列の控え・報告書のフォルダ・自動作成の済みの印と結果と ON／OFF・「明日の商談」の ON／OFF |

### 設定を変えるとき

`gas-code.txt` の先頭の設定ブロック（変えたら、貼り付け → 新バージョンでデプロイ）：

| 設定 | 内容 |
|---|---|
| `REC_AUTOSAVE_FOLDER` | 録音の保存先のフォルダ |
| `APPO_LEDGER` | `ENABLED`（台帳を使う）・`SHEET_ID`・`GID`（タブ）・`SORT`（`false` にすると、商談日の位置ではなく末尾に足し、並べ直しもしない）・`ORDER`（`asc`＝商談日の早い順／`desc`＝遅い順） |
| `APPO_CHECKS` | アポ取得報告の確認項目。**`index.html` の設定ブロックの `APPO_CHECKS` にも、同じ `key` で足してください** |
| `EXT_HISTORY_COLS` | `false` にすると、元シートに「架電回数（自動）」「架電履歴（自動）」を足さない・書かない |
| `EXT_HISTORY_SEP` | 履歴の区切り（既定はセルの中で改行。`" ／ "` にすると1行で並べる） |
| `REPORT` | `ISSUER`（報告書の作成者）・`FOLDER_ID`（PDF を置くフォルダ。空なら自動で作る）・`MONTHLY_AUTO`（毎月はじめの自動作成） |

`index.html` の設定ブロック：`DIAL_GUARD.WRONG_NG`（別の日に何回「不通」だったら、NG リストに入れるかをたずねるか。`0` でたずねない）。

## 元に戻す方法

1. GAS：デプロイ → デプロイを管理 → ✏️編集 → バージョンで v110 の版を選んでデプロイ。
2. GitHub：index.html・sw.js を v110 に戻して Commit し、各端末で「🔄 最新の状態に更新」。
3. 追加されたシートと列は、そのままで構いません（v110 は使いません）。元シートの「架電回数（自動）」「架電履歴（自動）」の列と、台帳に足した列・登録した行は残ります。不要なら、手で消してください。
4. 録音の保存先は、v110 のフォルダ（A アポインター毎日の架電音声）に戻ります。v111 の間に保存した録音は、新しいフォルダに残ります。

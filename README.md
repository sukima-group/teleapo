## ⑶ シフト申請（藤田さん）

### 症状

藤田さんがシフトを申請しても、管理者に通知が届かず、「申請されていない」結果になっていました。

### 原因：v108 で再現した3つの仕組み

v108 のサーバーの処理だけを見ると、申請の保存と通知はできていました。そこで、画面とサーバーを一緒に動かし、Galaxy A25 を想定したスマホ画面で再現テストを行いました。その結果、次の3つで、まさにこの症状が起きることを確かめました。

1. **サーバーの返事が JSON でないと、「送れた」とみなして消していた**（いちばん危ない）
   - Google のエラー画面・混雑・権限の確認画面などが返ってくることがあります。
   - v108 の送信の仕組みは、返事に小文字の「error」が無ければ成功として扱い、送信待ちから消していました。
   - その結果、藤田さんの画面は「登録済み（承認待ち）」なのに、サーバーには何も保存されず、通知も送られませんでした。消えた申請は、二度と送られません。
2. **サーバー（GAS）が古い版のままだと、保存されていないのに「登録済み」と表示していた**
   - GAS にコードを貼っても、「新しいバージョンでデプロイ」をしないと、古い版が動き続けます。
   - 古い版（v107）では、対象月が日付に化けて、管理者の一覧に出ません。
   - それでも画面は「登録済み」と表示し、開き直すと「まだ申請していません」に戻りました。
3. **管理者の画面は「今月」しか見ていなかった**
   - 来月分のシフトを申請しても、管理者の画面の既定（今月）では「未提出」に見えました。
   - 通知メールの宛先は、設定ファイルの1件（tereapo01.sukima@gmail.com）だけでした。

本番の記録は見られないため、藤田さんの端末で実際にどれが起きたかまでは特定できていません。3つとも直したうえで、v109 では次の「シフト受信ログ」で後から確かめられるようにしました。

### 修正

- **画面**
  - サーバーが「保存した」と返したときだけ「登録済み」にします。
  - 読めない返事のときは、申請を送信待ちに残して自動で再送します。届けば保存され、二重にはなりません。
  - 登録済みの表示に「受付番号」を出します。
- **サーバーの版の確認**
  - アプリを開くと、サーバーの版を確かめます。
  - 古ければ、全員の画面に赤い帯を出します（例：「アプリ v109／サーバー v107」）。
  - 管理者の画面には、直し方（デプロイの手順）も出します。
- **管理者の画面の先頭**
  - 🔔 **すべての月の承認待ち** を出します。来月分も見落としません。「📅 シフト表で開く」でその月のシフト表に移ります。
  - **今月・来月の提出状況**（例：12月 1/7名）と、未提出の人の名前を出します。
  - **保存できなかった申請**（直近7日）を理由つきで出します。
- **通知の宛先**
  - 設定ファイルの宛先に加えて、**管理者ログインのGmail** にも送ります。
  - 「🔐 管理者のセキュリティ」→「通知の宛先」から、5件まで足せます（SV・課長など）。
- **シフト受信ログ**（新しいシート）
  - サーバーが受け取った申請を、成功・失敗にかかわらずすべて残します。
  - 残す内容：日時、PIN、名前、対象月、申請ID、結果、理由、通知の結果、アプリの版、端末（例：Galaxy A25）。
  - 申請が届かないときは、まずこのシートを見ます。行が無ければ端末から届いていません。「エラー」なら理由が書いてあります。

## ⑵ 管理者画面をAIによる侵入から守る

### v108 までの穴

- 管理者PIN「9999」が、だれでも見られる公開ページ（index.html）に書かれていました。AIにページを読ませれば、すぐに分かります。
- サーバーの保護（ADMIN_GUARD）は、既定で「切」でした。全員のシフト・通知ログ・名簿の点検などは、だれから来ても受け付けていました。
- 経営管理システムの連携キーが、GitHub で公開されている gas-code.txt に書かれていました。このキーで、経営データの取り出しや、全員へのお知らせの配信ができました。
- 端末が「管理者です（forAdmin）」と名乗るだけで、名簿のメールアドレスが返っていました。

### 2026年の事例から分かったこと

- **AIエージェントは CAPTCHA（画像認証）を自分で解けます。** 2026年の発表では、AIエージェントが主要な画像認証を自動で突破し、回線を次々に替えてIPごとの回数制限も避けていました。このため、「画像認証」や「IPごとの回数制限」には頼らない方針にしました。
- **日本のサイトでも、2026年10月にAIエージェントによる攻撃が観測されました。** ログイン画面への総当たりや、パスワード再設定フォームへの自動アクセスが含まれていました。JPCERT/CC も、回数制限と多要素認証を呼びかけています。
- **NIST SP 800-63B-4（2025年の最終版）の考え方**
  - パスワードだけで守る場合は **15文字以上** にします。
  - 文字種を無理に混ぜさせるより、よくある言葉や流出済みのパスワードを断るほうが効果的です。
  - AAL2 という水準では、**30分操作がなければ再認証、12時間で再認証** とされています。

### 入れた対策

| 対策 | 内容 |
|---|---|
| 確認はサーバーで | 管理者専用の要求 **110種類** は、有効なログインがないとサーバーが断ります。公開ページには秘密を置きません |
| 15文字以上のパスワード | 長さを確かめます。会社名・システム名・同じ文字や並んだ文字が中心のもの、流出済みのものは断ります。流出の確認には Have I Been Pwned を使い、送るのはハッシュの先頭5文字だけです |
| 自動で作るボタン | 20文字の乱数（約116ビット・読み違えやすい 0/O/1/l/I なし）を作ります |
| パスワードの保存 | パスワードそのものは保存しません（PBKDF2-HMAC-SHA256・4000回） |
| メールの確認コード | 初回設定と「初めての端末」では、管理者のGmailに届く8桁のコードが必要です。**パスワードが漏れても、知らない端末からは入れません** |
| 総当たりへの待ち時間 | 4回まちがえると30秒、その後は倍々に延び、最大60分です。1日に試せるのは30回ほどです。5回・10回…の失敗で、管理者へ警告メールを送ります |
| 締め出し防止 | 失敗回数は「登録端末ごと」と「未登録の端末まとめて」で別々に数えます。攻撃されていても、管理者の登録端末は入れます |
| 見張り | ログインなしの管理者用の要求が1時間に20回・100回・500回届くと、管理者へメールで知らせます（サーバーはすべて断っています） |
| 自動ログアウト | 30分操作がない／12時間たつと、ログアウトします（画面とサーバーの両方） |
| 端末の管理 | 登録端末の一覧と削除、パスワード変更（ほかの端末のログインはすべて解除）。新しい端末の登録やパスワード変更はメールで知らせます |
| 連携キー | コードから外し、サーバーの設定（スクリプトプロパティ）だけに置きます。乱数で新しく作り、管理画面から表示・作り直しができます。公開されていた古いキーは使えません |
| 名簿 | 管理者ログインのときだけ、メールアドレスを返します |
| 自動操作ブラウザ | 自動操作されているブラウザ（webdriver）には、ログインの入力欄を出しません。偽装もできるため補助的な対策で、本当の守りは上の各項目です |

**パスワードを忘れたとき**：Apps Script のエディタで `adminResetPassword` を実行してください。初回設定からやり直せます。実行できるのは、GASの持ち主だけです。

**確認コードの送り先**：GASを作ったGoogleアカウントのGmailに届きます。別のアドレスにしたいときは、エディタの「プロジェクトの設定」→「スクリプト プロパティ」に `ADMIN_EMAIL` を追加してください。

**経営管理システムの連携キー**：経営管理システム（外部から kanriExport・kanri_push を呼ぶ仕組み）を使っている場合は、そちらのキーを新しいキーに変えてください。キーは「🔐 管理者のセキュリティ」→「連携キー」→「👁 全部表示」で見られます。

### 残るリスク（次の一手）

- **アポインター側のログイン**：今回守ったのは「管理者画面」です。アポインター側は、従業員番号と4桁の暗証番号のままです。サーバーの URL は公開ページに書かれているため、番号を総当たりされると、その人の架電リストを読まれるおそれがあります。次の段階として、アポインターのログインもサーバーで確かめる作りにすることをおすすめします。
- **gas-code.txt の公開**：v109 の gas-code.txt に秘密（PIN・キー）はありません。ただし、アポインターのメールアドレスとシートのIDが書かれています。GAS には貼り付けるだけで動くため、GitHub の公開リポジトリからは外すことをおすすめします。
- **パスキー**：2026年に最も効果が高いとされる「パスキー（指紋・顔での認証）」は、今回の構成（GAS）では検証の実装が大きいため、入れていません。次の段階の候補です。

## ⑴ 通話録音の自動移動（Galaxy A25 → 管理者のGoogleドライブ）

### 仕組み

1. **Galaxy の自動録音**
   - Galaxy は通話を自動で録音します。
   - 保存先：「内部ストレージ › Recordings（または Recording）› Call」
   - 形式：.m4a
   - ファイル名：「通話記録 番号_年月日_時刻」（例：通話記録 09012345678_261104_103015.m4a）
2. **最初の1回だけフォルダをつなぐ**
   - アプリのホームの「📂 録音フォルダをつなぐ」を押し、このフォルダを選びます。
   - Chrome 132（2025年1月）以降は、Android でもアプリがフォルダを読めます。
3. **あとは自動**
   - アプリを開いている間、**電話から戻るたび** と **3分ごと** に、新しい録音を探して送ります。
   - 送り先は、管理者のドライブの録音フォルダ（設定ファイルの `REC_ROOT_DEFAULT`）の「担当者／年月／日」です。
   - 保管庫にも「藤田直美_2026-11-04_1015.m4a」のような名前で集めます。
4. **安全に移動する**
   - ドライブ上でファイルの大きさが一致したことを確かめてから、スマホの元ファイルを消します。
   - 確かめられなかったものは消しません。
   - 送ったファイルは記録し、二度送りません。
   - 録音中（15秒以内）のファイルや、音声以外のファイルには触りません。
5. **管理者が確認できる**
   - 管理画面の先頭に、全員分の状態を出します（動いている／止まっている／許可待ち／未接続、今日の送信件数と架電件数、エラー）。

あわせて、サーバーが Galaxy のファイル名（年が2桁「261104_103015」）を正しく読めるようにしました。v108 までは通話の日時を読めず、「20」を含む電話番号も読めなかったため、架電記録との照合がずれていました。

### できないこと

- **アプリを閉じている間は動きません。** ブラウザで動くアプリの制約です。
  - 閉じている間の録音は、次にアプリを開いたときに送ります（30日以内のもの）。
  - 通話はアプリから発信するため、業務中の録音は数分以内に移動されます。
- スマホの再起動のあとなどに許可が外れた場合は、ホームの「🔓 1回タップして再開」を押します。
- Chrome 132 以降が必要です。Samsung Internet でアプリを入れた場合は、Chrome で開き直してください。

### 各アポインターの Galaxy での設定（1人1回）

1. **自動録音をONにする**：電話アプリ → 右上の︙ → 設定 → 通話を録音 → 「通話の自動録音」をON（すべての通話）
2. **フォルダをつなぐ**：川嶋メソッドのホームの「🎙 通話録音の自動送信」→「📂 録音フォルダをつなぐ」→ 次の順に進みます。
   - 「内部ストレージ」
   - 「Recordings」（または Recording）
   - 「Call」
   - 下の「このフォルダを使用」
   - 「許可」
3. ホームに「✅ 自動送信 ON」と出れば完了です。

実ブラウザの通しテストでは、次の流れを確かめました。

1. 藤田さん（Galaxy A25 を想定）が暗証番号でログインし、録音フォルダをつなぐと、2件が移動する。
2. 来月のシフトを申請すると「登録済み（承認待ち）」「受付番号」「管理者へ通知済み」と出る。受信ログに版と端末つきで残る。
3. サーバーが JSON 以外を返すと、v108 は「登録済み」と表示して申請を消す（再現）。v109 は送信待ちに残し、戻ったら自動で保存する。
4. サーバーが古い版（v107）だと、赤い帯と「保存されていません」を出す。
5. 管理者は 9999 では入れない。初回設定でコードを受け取り、パスワードを自動で作って設定する。
6. 管理画面の先頭に来月分の承認待ちと提出状況・録音の状態が出て、シフト表から承認できる。現況の集計もログインで取れる。収支はパスコードなしで開ける。
7. 30分たつと、管理者ログインへ戻る。
8. 自動操作のブラウザには入力欄を出さず、サーバーを直接呼んでも、シフト・名簿のメール・収支・経営データは返らない。

**未検証**：実際の Gmail の送信と1日の上限、本番のスプレッドシートとGASでの動作と処理時間、実機（Galaxy A25 の Chrome）でのフォルダの許可と削除、藤田さんの端末で実際に起きた原因（上の3つのどれか）。

## ⚠️ 導入手順

1. **控えを取る**：メインと管理者用のスプレッドシートで、ファイル → 版の履歴 → 今の版に名前を付けます。
2. **GAS**：「コード.gs」を全消去 → `gas-code.txt` を貼り付け → 保存。
3. **GAS**：デプロイ → デプロイを管理 → ✏️編集 → バージョン「**新バージョン**」→ デプロイ。URLは変わりません。
   - **ここを忘れると古い版が動き続けます。** v108 の不具合の原因の1つです。v109 では、忘れると全員の画面に赤い帯が出ます。
4. **GAS**：エディタで関数 `adminSetupCheck` を1回実行します。
   - 権限の確認画面が出たら「許可」します。
   - ログに、確認コードの送り先・今日のメールの残り・シフトの通知先・サーバーの版が出ます。
5. **GitHub**：`index.html`・`sw.js`・`README.md` を上書きして Commit します。
   - **tests フォルダは上げないでください。**
   - `gas-code.txt` は上げなくても動きます（GASに貼るだけ）。公開リポジトリからは外すことをおすすめします。
6. **全端末・PC**：アプリを開き「🔄 最新の状態に更新」を押します。
7. **管理者**：ログイン画面の「🔐 管理者ログイン」→「📧 設定コードを送る」→ Gmail に届いた8桁を入れます。
   - 「🎲 自動で作る」を押し、パスワード管理アプリか紙に保存します。
   - チェックを入れて「このパスワードに決める」を押します。
8. **管理画面の先頭**で確かめます。
   - 赤い帯が出ていないこと（出ていれば手順3）。
   - 「🔐 管理者のセキュリティ」→「通知の宛先」に、通知を受け取りたい人が入っていること。「✉ テスト通知を送る」で届くかも確かめます。
   - 経営管理システムを使っている場合は、「連携キー」の新しいキーをそちらに設定します。
9. **各アポインターの Galaxy**：上の「各アポインターの Galaxy での設定」を1人1回行います。

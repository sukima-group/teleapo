## 🆕 v52：架電数の二重計上を根本から解消

### 原因（1回の架電が2回になっていた理由）
数える場所が**2箇所に分かれていた**ことが原因でした。

1. **発信ボタンを押した瞬間**に「架電数」を+1していた
2. **結果を保存すると、その場で次の会社へ自動発信（チェーン）**が走り、そこでもう一度+1していた

そのため「1件かけて結果を入れただけ」で **2** と表示されていました。
加えて、発信画面を開いてすぐ閉じた（誤タップ）場合でも、オートコール中は自動で「不在」が記録され、履歴が増えていました。

### 解決：数える場所を1つだけにする
**架電数を「記録された履歴の件数」から常に算出する方式**に変更しました。発信ボタンを押した時点では一切数えません。

| 場面 | v51まで | **v52** |
|---|---|---|
| 発信ボタンを押す | +1 される | **数えない** |
| 結果を保存する | 次の発信で更に+1 | **履歴1件＝架電1件** |
| 誤タップで4秒未満に戻る | 「不在」が記録される | **記録しない**（同じ会社にとどまります） |
| 取消（↩ Undo） | 件数が減らない | **正しく減る** |
| サーバー同期のあと | ずれることがある | **常に履歴と一致** |

これにより **「履歴の件数」と「架電数」が食い違うことが原理的に起こりません**。

### 二重記録の防止（3重の安全策）
1. **端末側**：直近15秒以内に同じ電話番号の記録があれば、新規追加せず**最新の結果で置き換え**（オートコールの自動「不在」→本人が「断り」を入力、のようなケースで1件にまとまります）
2. **サーバー側**：架電結果シートでも、直近15秒以内の同じ担当者×同じ電話番号は**行を追加せず上書き**
3. **空発信の遮断**：4秒未満で戻った場合は「発信されませんでした（記録していません）」と表示し、記録も前進もしません

> ※ 20秒後などの正当な再架電は、これまでどおり**別の1件**として記録されます。

### 確認手順
1. ログイン画面に「**v52**」
2. **1件だけ**架電して結果を保存 → ホームの「本日の架電」が **1** であること（2にならない）
3. 発信ボタンを押してすぐ戻る → 「発信されませんでした（記録していません）」と出て、**件数が増えない**こと
4. 「↩ 取消」を押す → 件数が **1つ減る** こと
5. 履歴画面の件数と、ホームの架電数が **一致している** こと

### 既存データについて
これまでに二重計上された過去の数値は自動では直りません。**ログインし直す（または画面を開き直す）と、その日の架電数が履歴から再計算されて正しい値に戻ります**。スプレッドシート側に重複行が残っている場合は、お手数ですが該当行の削除をお願いします（今後は発生しません）。
